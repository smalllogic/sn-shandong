# 分类集合页筛选设计研究记录

- 日期：2026-11-19；研究模式：设计研究简报。
- 原始请求：研究后台指定筛选字段、前台大类显示并执行筛选的设计。
- 问题链：异构产品参数 → 分类适用属性 → 大类集合页筛选 → 管理员可控且客户易懂的交互。
- 核心问题：如何分开属性数据规则与集合页筛选配置，并让大类和子类的筛选具有一致含义？
- 受众：网站所有者及 Rails 开发者；输出：中文方案及开发结构，无功能实施。
- 范围：现有 Rails 分类树、商品规格、价格、后台配置、前台桌面和移动交互、范围语义。
- 不主张：这是普适最优方案或经过该站客户测试的结论。

## 来源与方法

初始三条检索属于探索性检索，发生在本文件落盘前；不将其包装为事先注册的方案。
检索渠道：网页搜索；完整查询：
1. site.baymard.com product list filtering applied filters multiple values same filter
2. site.help.shopify.com search discovery filters category metafield filters
3. site.algolia.com doc disjunctive faceting counts filters

后续选择原始 UX 研究机构公开文章、平台官方配置说明、搜索引擎官方文档和 W3C 可访问性资料。
排除：论坛建议、无方法描述的营销最佳实践、未读正文的搜索摘要。
反向检查：只有公共属性的父类筛选是否足够；任意聚合字段是否误导；区间筛选是否有唯一解释；即时刷新是否总适合移动端。
停止规则：覆盖配置、跨分类语义、筛选逻辑与统计、范围及可访问性四组问题，并逐条核对本地代码适配点后停止。
证据限制：未访谈本站客户、未审计实际商品参数覆盖率、未作效果实验。商业研究机构和厂商资料有产品适用范围与商业利益。
